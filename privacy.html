iSnips Privacy Policy

Updated October 16, 2026 · Chrome extension 2.0.0

iSnips saves text you choose to clip and notes you write. The extension works locally without an iSnips account. We do not run analytics, advertising, tracking, or a server that receives your extension records.

What the extension accesses

When you save a selection, iSnips stores the selected text, page URL, domain, page title and timestamps. Notes can include the current page URL when “Attach page” is checked. Saved highlights include their source URL and text positions so they can be restored when you revisit that page. Custom folder names and record assignments are stored locally using the existing spaces data. Folder definitions are included in JSON exports and local snapshots and, when you enable synchronization, sent to your selected cloud service. Existing space assignments and preferences are retained.

The content script accesses page text to capture your selection and restore saved highlights. It does not upload the pages you visit or maintain a separate browsing-history log. Site access allows these features to work on pages you visit. You can disable capture and highlights for a domain and its subdomains in Settings, or restrict site access using Chrome’s extension controls.

Optional clipboard history

On first use, or after an upgrade introduces clipboard capture, iSnips prominently explains this feature and asks you to choose Agree and enable or Not now. No copied text is recorded until you explicitly agree. Dismissing the notice does not give consent. An existing paused preference is retained. After agreeing, auto-save is enabled and can be paused in the Clipboard category. While it is on, iSnips records text you copy or cut with the browser’s normal copy controls on supported web pages, along with its source URL, domain, title and copy time. It keeps only the latest 99 unique text entries in this browser profile. Copying the same text again moves it to the front. It does not read the system clipboard, monitor other applications, capture password inputs, or save copies from incognito tabs or domains you disabled. Chrome-protected pages and embedded frames are not captured. Website copy buttons that use their own clipboard code may not be captured.

You can pause auto-save, remove an entry or clear this history in the Clipboard category. History is temporary and is excluded from synchronization, JSON exports and local backup snapshots. “Save as note” creates a regular note, then removes that entry from the history; that note follows your normal export, backup and optional sync settings. Clearing local data also removes history and resets preferences to their defaults, including the consent choice; capture stays off until you agree again.

Local storage and credentials

Records, highlights, spaces and preferences are stored in your browser profile using IndexedDB and Chrome storage. Local snapshots and a recovery copy of records also remain in that profile. An unfinished quick note is kept in browser session storage until saved, cleared or the browser session ends. Your versioned clipboard consent choice and decision time remain on this device; they are excluded from synchronization, exported backups and local record snapshots. A backup cannot authorize clipboard recording.

If you configure WebDAV, its address, username and password are stored locally to connect to that server. These credentials are available to trusted extension pages, not content scripts. They are not separately encrypted by iSnips. Chrome’s native Google authorization tokens are managed through its identity API. The optional Brave/web connection opens Google’s authorization page using the browser identity API and stores only a short-lived access token and expiry in trusted extension session storage. A local preference remembers the selected authorization method. The web connection does not collect your Google password, use a client secret, retain a refresh token or send authorization tokens to an iSnips server. Web tokens and authorization-method preferences are excluded from exports, synchronization and backup snapshots. Protect access to your device and browser profile.

Optional synchronization

Synchronization is off by default. When you enable a service and synchronize, iSnips sends records—including saved text, source information, timestamps and deletion markers—and folder definitions, names, ordering, record assignments and folder deletion markers to that service. Highlights, preferences, temporary clipboard history and local snapshots are not synchronized in this version. Automatic sync runs only when you configure it.

  • Google Drive: The extension requests the drive.file scope to access files it creates or that you authorize. It stores iSnips/snippets.json in an ordinary folder in your Drive, not a hidden application-data folder. Access is governed by your Google account, folder sharing and Google’s policies. iSnips does not change sharing permissions.
  • WebDAV: The extension sends records, folder definitions and authentication credentials to the server you configure. Remote connections require HTTPS; HTTP is allowed for localhost development only. The server operator controls storage and access under its own policies.

We do not sell data, use it for advertising, or transfer it to data brokers or credit services. Data received through Google APIs is used only to provide the synchronization you request and is handled in accordance with the Chrome Web Store User Data Policy and its Limited Use requirements.

Export, deletion and your choices

You can export a JSON file containing records, highlights, spaces and supported preferences. Export files and new local snapshots exclude sync configuration, connection credentials and tokens. Exported records may themselves contain personal information or secrets you saved; keep the file private.

Deleting a folder returns its records to Unfiled and removes the folder from the interface. Its last name and deletion timestamps remain locally and in synchronized files as a deletion marker, preventing old files or offline renames from restoring it. Folder deletion does not remove record text.

Moving a record to Trash is reversible. Emptying Trash removes it from the interface and retains deletion markers to propagate deletion during sync; underlying record content and earlier snapshots can remain in storage. “Clear local data” deletes the extension’s local records, folders and deletion markers, highlights, preferences, credentials, recovery copies, session drafts and snapshots, and stops local synchronization.

Clearing local data or disconnecting a service does not delete files already on Google Drive or a WebDAV server. Delete those remote files and any exported backups separately if you no longer want them. Reconnecting to an existing sync file can download its records again. Disconnecting the web connection clears its credentials on this browser and stops local synchronization; it does not revoke authorizations on other devices. The native Chrome disconnect also attempts Google authorization revocation. You can revoke iSnips access in your Google account, which may affect other devices using the same Google project.

External links and contact

Source links, feedback and support links open only when you choose them. Those websites receive your visit and apply their own privacy policies. Contact us through the iSnips issue tracker; do not post private records or passwords in public issues.
